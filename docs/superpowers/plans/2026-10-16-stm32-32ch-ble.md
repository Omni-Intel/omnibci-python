# STM32 32ch BLE Python Implementation Plan

> **For agentic workers:** Use subagent-driven-development to implement and independently review this plan.

**Goal:** Deliver a tested Windows ABI3 wheel on branch 32ch supporting the GUI's E73 BLE STM32 board and retaining ESP32 compatibility.

**Architecture:** Reuse SDK cc76914882d2b84bc5c14780b136cd82e5083465. A small native STM32 session owns the SDK driver, control acknowledgements and bounded data delivery; the existing Python Board selects its backend explicitly. Do not copy radio or packet parsing algorithms.

**Tech Stack:** Rust/PyO3, existing SDK/crossbeam-channel, Python/numpy, maturin, uv, pytest.

## Global Constraints

- Work only in omnibci-python-32ch on 32ch; preserve GUI/firmware and SDK source.
- Python >=3.11, package omnibci, ABI3, Windows x64 local verification and existing six-platform CI matrix.
- No hardcoded local machine paths in executable code/tests/CI. Commit uv.lock; run uv sync --locked --all-extras followed by uv run --no-sync commands.
- Version 0.2.0 for this added device support; keep source, metadata and runtime version consistent.
- AE/BE-capable 32.0.5 firmware required; 32.0.4 excluded. No flashing or real device commands as part of unattended tests.
- Bounded queues/deadlines, preserve partial data, stop/SD acknowledgement, explicit failure/overflow, no automatic reconnect/mode switching.
- Source SDK commit currently local; do not claim remote reproducibility or publish until pinned commit is remotely retrievable.
- Follow approved spec docs/superpowers/specs/2026-10-16-stm32-32ch-ble-design.md.

## Task 1: Implement the device path and its runnable checks

Files: Cargo.toml/Cargo.lock, pyproject.toml/uv.lock, src/lib.rs, new src/stm32_session.rs, python/omnibci/{api.py,__init__.py,_native.pyi}, tests/test_stm32.py and Rust tests in the session module. SDK gitlink only; no SDK source changes.

Interfaces:
- Board.connect(device, *, timeout=15.0, device_type="esp32"); Board.discover(*,transport="serial",timeout=10.0,device_type="esp32"). STM32 discovery results retain device type so connect(info) cannot select ESP32 accidentally.
- Stm32Config fields: mode, enabled_mask, bias_mask, loff_mask, gains (32), verified. Defaults mirror SDK Configuration, with loff_mask=0. Validate masks/subsets/mode/gains both Python and Rust trust boundaries.
- decode_frames(data, *, gains=None, device_type="esp32"); default gains resolve to 8 or 32 values. Existing omitted/default ESP32 calls retain behavior.
- Native packed data adds channel_count/status width for reshape; missing width on old test fixtures may default to ESP32 shape. Arrays immutable, sample-major; raw status preserves 4 ADS chips for STM32.
- Map STM32 errors to existing public exceptions. Internal adapter exact signatures may follow current code's patterns; avoid public abstractions not needed by these endpoints.
